TERMINA 80

A 1984 computer. Built in 2026.

A phosphor terminal on an ESP32-S3, with real processes, a scripting shell, Lua, Git and a windowed desktop. Your PC's keyboard and mouse reach it over Wi-Fi, and a Pico 2W drives any HDMI screen.

Wiring

The screen is any HDMI display, driven by the Pico 2W video card (next chapter). The rest of the machine is a buzzer and two LEDs. All of these pins sit on the left header (J1) of the DevKitC-1. Do not use GPIO 26 to 37 (flash and octal PSRAM), 19/20 (native USB) or 43/44 (serial port).

Sound

You need a passive buzzer: + terminal on IO7, − terminal on GND. A power-hungry magnetic buzzer goes behind an NPN transistor (base tied to IO7 through 1 kΩ, with a diode across the buzzer). The pin is set in firmware/src/sound.cpp.

The LEDs

The disk LED is on IO5 and the network LED on IO6. Each access lights them for at least 40 ms so you have time to see it.

HDMI video card

TERMINA drives any HDMI screen. A Raspberry Pi Pico 2W acts as the video card, a bit like the picture chip of an 80s console: the ESP32 sends it a description of the screen over SPI, and the RP2350 builds each line just before its HSTX block sends it out as 640×480 at 60 Hz DVI.

ESP32 ──SPI 20 MHz──▶ Pico 2W (scene, line by line) ──HSTX/DVI──▶ HDMI screen

What the Pico draws itself

  • The shell: a text screen of cells, font, 16 colors and cursor. A typed character costs a few bytes on the link.
  • The desktop: the background, each window, the taskbar and the open menu are 4-bit planes in the Pico's RAM. Moving or raising a window only changes positions; only rows whose contents changed travel.
  • The isometric world of the iso library: the sprites and the map go once, then only the camera and the people; the Pico draws what changed.
  • The mouse pointer and the scanlines, in every mode.

The rest (paint, screen savers, a desktop too full for the Pico's RAM) still goes as strips of 16 lines into a 640×480 framebuffer in 256 colors (RGB332). The text screen, the desktop and the world show the exact colors. Text modes are 80×30 or 106×40 (mode 106|80).

Pico 2W → HDMI plug

Use a bare 19-pin HDMI male breakout. Each of the 8 signals goes through a 270 Ω resistor (220 to 330 Ω also work). Keep the wires under 10 cm and twist each +/− pair together.

Hold BOOTSEL while plugging the Pico in to flash it the first time. Firmware

Building and flashing go through PlatformIO:

pio run -d firmware -t upload -t monitor

Wi-Fi

  • Copy firmware/include/secrets.example.h to secrets.h and put your network in it.
  • You can also configure nothing. TERMINA then opens a TERMINA-XXXX access point (password termina80, IP 192.168.4.1). Once the PC is connected, type:
A>wifi "MyNetwork" password

The network is saved in NVS and the machine reboots onto it. Until Wi-Fi is up, the serial monitor (115200 baud) works as a keyboard.

Plug the USB cable into the port marked UART. The partition table is firmware/partitions.csv: 4 MB for the program, 11.9 MB for A:. A freshly flashed board formats A: on first boot.

Keyboard and mouse

The termina-input program finds the machine on its own through mDNS:

go run ./cmd/termina-input
# or forcing the address
go run ./cmd/termina-input -addr 192.168.4.1:2323
  • When the window has focus, everything you type goes to TERMINA. AZERTY accents are translated on the PC side.
  • A click in the window captures the mouse and F12 releases it.
  • -sens 1.5 sets the mouse sensitivity.

USB mouse

A boot-protocol USB mouse can also plug straight into the port marked USB (IO19/IO20) through a USB-C OTG adapter. It works without termina-input, in the shell programs, PAINT and TERMINA WIN, next to the PC mouse.

Hubs are not supported. The port must supply 5 V: some DevKitC-1 clones need their USB-OTG pad closed, otherwise use an OTG adapter with its own power input. If the mouse LED stays off, power is the problem.

Sharing files

share on starts a small file manager on port 80 and share off stops it. From any browser on the same network, open http://termina.local/ (or the address share on prints).

  • Browse A:, download, rename and delete files and folders, create folders.
  • Drop files or whole folders on the page to upload them. A file is written as name.part and only replaces the old version once complete.
  • The machine keeps running during a transfer: the server has its own task on core 0.
There is no password: while sharing is on, anyone on the network can read and write A:. It is off at boot.

Emulator

termina-emu runs the real firmware on the PC, and the video card with its own code. The window serves as HDMI screen, keyboard, mouse and speaker. It is handy for trying a Lua program, an application or a theme without flashing the board.

The firmware's C++ code is compiled by cgo, so gcc is required. On Windows, use the MSYS2 one (pacman -S mingw-w64-x86_64-gcc).

go generate ./internal/emu && PATH=/c/msys64/mingw64/bin:$PATH CGO_ENABLED=1 go run ./cmd/termina-emu
Run go generate before each build that follows a firmware change. The Go cache does not see the C++ sources included from firmware/, so the generator writes their fingerprint into internal/emu/fw_*.cpp. It also produces the built-in Lua programs.
  • The A: drive is the %AppData%\termina\A directory (-disk option). NVS settings are stored next to it, in nvs.txt.
  • The mouse follows the PC pointer, without capture. -scale 1 makes the window 640×480 (the default is twice that) and -mute turns the sound off.
  • -type types text after startup and -shot f.png saves the screen then quits. In -type: \n Enter, \e Esc, \s Ctrl+Esc, \c Ctrl+C, \z Ctrl+Z, \u/\d arrows, \p a one-second pause.
  • Wi-Fi is simulated and always connected. The browser goes through Go's network stack, which verifies TLS certificates. ping times a TCP connection to port 80 or 443.
  • The firmware is not modified: internal/emu/hal/ replaces Arduino, LittleFS, Preferences, FreeRTOS, HTTPClient and the bits of the Pico SDK the video card uses. With TERMINA_MEM_SCALE=2, the Lua memory limits are doubled, since a Lua object takes about twice as much room on a 64-bit PC.

Processes and jobs

Each command runs in a process of its own, and several run at the same time.

A>cat log.txt | grep -i error | wc -l

A>git clone https://github.com/rxi/json.lua > clone.log 2>&1 &
[1] 5
A>jobs
[1]+  Running              git clone https://github.com/rxi/json.lua > clone.log 2>&1
A>mkdir out && echo "shell pid $$" > out/info.txt

Ctrl+C interrupts the foreground job and Ctrl+Z stops it. fg %1 brings a job back, bg %1 lets a stopped one go on behind, kill %1 ends it (kill -l lists the signals). A background job that waits for a key stops until fg. Jobs keep running in TERMINA WIN, and a job started in a desktop Terminal ends (HUP) when its window closes.

ps shows the processes: R running, S sleeping, T stopped, + has the keyboard.

At the prompt

A long line continues on the next rows. ↑/↓ go through the last 200 lines (history lists them), and ^R searches them: type part of a command, ^R again for an older one, Enter runs it. Tab completes names. ^U, ^K and ^W cut to the start, to the end or the previous word into the clipboard, ^Y pastes it, so text copied in edit or Notepad can be pasted here.

Unquoted *, ? and [abc] become the matching file names (ls *.lua, rm old/*.txt); quotes keep them as they are. alias ll='ls -l' gives a command a short name. If a /.profile script exists, the prompt runs it when it starts: the place for aliases and variables.

Under the hood, each process is a FreeRTOS task with its own stack, but only one runs at a time: they take turns whenever the running one waits (keyboard, sys.sleep, a full pipe), or every 20 ms for a Lua program. The ESP32-S3 has no MMU, so separate Lua states keep programs apart. At most 12 processes run at once, each needing about 80 KB of internal RAM. Commands that change the shell (cd, export, fg…) or take over the screen cannot be piped or put in the background.

Shell scripts

The shell understands a small sh/bash language, at the prompt as in files. A name.sh file in the current directory or in / runs as the command name, in its own process: it can be piped, put in the background and interrupted like any command. source name.sh (or . name.sh) runs it inside the shell instead, keeping its variables, functions and directory. An unfinished command at the prompt goes on on the next line after a > .

# count.sh: counts the lines of the files given
total=0
for f in "$@"; do
  if [ ! -f "$f" ]; then echo "$f: not found" >&2; continue; fi
  n=$(wc -l < "$f")
  echo "$f: $((n))"
  total=$((total + n))
done
echo "total: $total"

Ctrl+C and Ctrl+Z act on the whole script, since its commands stay in its process group. edit highlights keywords, variables, strings and comments in .sh files and files with a shell #! line.

Programming in Lua

Programs are .lua files on the A: drive. Type edit game.lua to write one, then game to run it. At boot, hello.lua and snake.lua are copied to A: if they are not there already. They are examples to read and modify.

-- stars.lua
term.cls()
while true do
  local ev = key.poll()
  if ev and ev.type == "key" and ev.key == "esc" then break end
  term.cell(sys.random(term.cols()) - 1, sys.random(term.rows() - 1), "*", 14)
  sys.sleep(30)   -- yields: the screen refreshes
end

It is standard Lua 5.4, with 32-bit numbers and the string, table, math, utf8 and coroutine libraries. io and os are TERMINA's own: standard input and output, environment and processes. A script gets at most 1 MB of memory, taken from PSRAM. If it goes over, it stops with "Out of memory" and the rest of the machine keeps running. Coordinates start at 0, row 0 is the status bar and an attribute is background * 16 + foreground.

Git

git is a real Git client written in Lua. It speaks the smart HTTP(S) protocol of GitHub, GitLab or Gitea. The repository it creates is an ordinary Git repository, which the PC's git can read.

A>git config user.name "Ada Lovelace"
A>git config user.email ada@example.org
A>git clone https://github.com/rxi/json.lua
A>cd json.lua
A:\json.lua>edit README.md
A:\json.lua>git add .
A:\json.lua>git commit -m "From TERMINA"
A:\json.lua>git config user.login mylogin
A:\json.lua>git config token ghp_xxxxxxxx
A:\json.lua>git push

Other commands: status, diff [--cached], log [-n N], show [commit], rm f, restore [--staged] f, branch [name], switch branch, pull. The name, email, login and token are kept in NVS and never in the repository. For GitHub, the token is a personal access token with write access to the repository.

A few limitations: the clone is shallow (latest commit only) and objects are not compressed, so the repository takes about twice the size of the files. pull can only fast-forward: if both sides have different commits, it stops without merging. Committing requires network time (NTP).

To develop the client on the PC, there is a test bench: sh firmware/test/host/build.sh, then hostlua.exe --root /tmp/disk firmware/lua/git.lua clone <url>.

TERMINA WIN

win starts a Windows 3.1-style desktop, driven by the mouse. There are icons to double-click, a taskbar with a Start button and a clock, and windows you move by the title bar and resize by the corner. Colors follow the theme.

  • Shortcuts: Alt+Tab, Alt+F4, Ctrl+Esc for Start.
  • Bundled applications: Files, Notepad (Shift+arrows select, Ctrl+C/X/V use the clipboard), Clock, Settings (theme, wallpaper, screen saver) and Terminal.
  • Terminal is a real text terminal in a window, with its own current directory: commands, Lua programs (git, pkg, your scripts), telnet, edit, snake and sysinfo run inside it, live, keyboard included, pipelines too. Closing the window sends HUP to its jobs. Only paint and web take over the screen then give the desktop back.
  • Start > Exit to DOS returns to the prompt.

Writing an application

An application is a .lua file on A: whose header contains -- @app Name, and optionally -- @icon name. All applications run at the same time, each in its own coroutine. An application must yield through win.event() or sys.sleep(), otherwise it is stopped after 4 seconds. An error only closes the application at fault.

-- @app Hello
local f = win.open{title = "Hello", w = 160, h = 60}
f:cls(15)
f:text(10, 20, "Hello!", 1, nil, "vga")
while win.event().type ~= "close" do end
